# 11.1 · Open notes in a Keep-style modal

**Goal:** Opening an existing card (a saved note, a history version, a trashed note, or any future card) shows it in a centered modal over the page, like Google Keep, so the board never shifts. Creating a new note through "Take a note" stays inline, as it is now.

**Spec:** Flow §6 (board), §8 (leaving a note cuts a version), §9 (history), §16 (trash), and the Phase 1 "UI" paragraph in §19 ("UI matches Google Keep exactly"). The owner approved this after task 11. Schema: none.

**Model:** Claude Sonnet 5.5.

**Prompt:**

```text
Read AGENTS.md, brief.md, sections 6, 8, 9 and 16 and the Phase 1 "UI" paragraph of section 19 in docs/Tracepad-Full-Flow.md. Then read web/src/features/board/Board.tsx, web/src/features/editor/NotesHome.tsx and Editor.tsx, web/src/features/history/History.tsx, web/src/features/trash/TrashUi.tsx and web/src/app/AppRoutes.tsx.
Do task 11.1. Right now, opening a saved note renders the editor in place of the "Take a note" bar, which shifts the board. The owner approved this change:
- Add one shared modal in web/src/ui/ (NoteModal) and use it for every opened card: saved notes on the board (all views, including Archive and Labels), history versions (/history/<note-uuid>/<version-uuid>), and trashed notes. Any future card that opens must use it too.
- Look and size like Google Keep: centered, about 600px wide (full width minus 16px margins on narrow screens), height fits the content up to the viewport minus about 64px, with the body scrolling inside. The note's color is the background, with rounded corners, a shadow and a dim backdrop over the page.
- No layout shift: the page under the modal doesn't move or scroll. The opened card keeps its slot on the board but is hidden while open, as Keep does.
- Closing: a "Close" button, Esc, or a click on the backdrop. For an editable note, closing counts as leaving the note (section 8), so it cuts a version by the same rules. Ctrl+S still works inside.
- Accessibility: role="dialog", aria-modal, focus moves into the modal, stays trapped inside it, and returns to the card on close.
- Contents don't change: each modal shows what that card shows today (the editor, a version view, or a trashed note with its actions). Only the container changes.
- Creating a new note via "Take a note" stays inline exactly as it is now. Don't change it.
Keep the change scoped to opening cards. Reuse existing components; don't duplicate the editor.
Always write tests for the feature you're building, before or alongside the code. Then run ./tests/run-all.sh; every test must pass. Report.
```

**Done when:**
- Component tests for NoteModal: dialog role and aria-modal, Esc, backdrop click and Close all close it, focus is trapped and then returned to the card.
- Component tests: a saved note, a history version and a trashed note each open in NoteModal; "Take a note" still opens inline with no modal.
- Unit test: closing an edited note in the modal cuts one version; closing an unchanged one cuts none.
- A Playwright test (`web/e2e/note-modal.spec.ts`): open a card and check that the other cards' positions haven't moved; the modal is about 600px wide on desktop and full width minus margins at 375px; edit, press Esc, and the card shows the new text; open a version and a trashed note in the modal.
- `./tests/run-all.sh` exits 0.
