# 12.1 · Fix the note popping up on refresh; Restore for trashed notes

**Goal:** Refreshing the page never reopens a note by itself. A note opened from the trash offers "Restore" instead of "Move to trash", using the same restore logic as the trash card.

**Spec:** Flow §16 (restore from trash: back where it was, history entry, syncs). Task 11.1 (the note modal). Schema: `notes.trashed_at`, `history_events`, `outbox`.

**Model:** Claude Sonnet 5.5.

**Prompt:**

```text
Read AGENTS.md, brief.md, and section 16 of docs/Tracepad-Full-Flow.md. Then read web/src/app/AppRoutes.tsx, web/src/features/editor/NotesHome.tsx, web/src/features/editor/Editor.tsx and web/src/ui/NoteModal.tsx.
Do task 12.1. The owner approved two fixes:
1. Bug: after a refresh, a note pops up in the modal by itself.
   Likely cause: "Back to note" in history does navigate('/', { state: { openNoteId } }). The browser keeps history state across a reload, and openedOnArrival is a ref that resets, so NotesHome opens the note again on every refresh.
   Confirm the cause first (reproduce it in a test). Then fix it: after the board consumes openNoteId, replace the history entry with the same path and no state. A refresh then shows the plain board. "Back to note" must still open the note once.
2. Trashed notes: a note opened from the Trash view still shows "Move to trash". Hide that button for trashed notes and show "Restore" in its place.
   "Restore" must use the same path as the Restore button on the trash card (NotesHome restore(): restoreFromTrash, clear a matching undo, refresh). Then close the modal. The note goes back where it was, with pin and color kept and a history entry (section 16).
Keep the change scoped to these two fixes.
Always write tests for the feature you're building, before or alongside the code. Then run ./tests/run-all.sh; every test must pass. Report the confirmed cause of the bug.
```

**Done when:**
- A component or route test: "Back to note" opens the note once; re-rendering with the same history entry (a simulated reload) doesn't open it.
- A Playwright test: open history, click "Back to note", close the modal, reload, and no modal appears.
- Component tests: a trashed note's modal has "Restore" and no "Move to trash"; an active note's modal is unchanged.
- A Playwright test: trash a note, open it from Trash, click "Restore"; the modal closes and the note is back on the board with its pin and color; history shows "restored".
- `./tests/run-all.sh` exits 0.
