# 10.1 · Version history as its own page

**Goal:** Give version history its own page, `/history/<note-uuid>`, that looks and behaves like the board: side list kept, versions shown as board-style cards, the same sort and grid/list controls, and old versions opened like notes.

**Spec:** Flow §9 (version history) and §6 (board), plus the Phase 1 "UI" paragraph in §19. The owner approved this layout after task 10. Schema: `note_versions`, `history_events`.

**Model:** Claude Sonnet 5.5.

**Prompt:**

```text
Read AGENTS.md, brief.md, sections 6 and 9 and the Phase 1 "UI" paragraph of section 19 in docs/Tracepad-Full-Flow.md. Then read web/src/features/history/, web/src/features/board/Board.tsx, web/src/features/editor/NotesHome.tsx and web/src/app/App.tsx.
Do task 10.1: rework the history from task 10 into its own page. The owner approved these changes:
- Route: history lives at /history/<note-uuid> (React Router). An old version opens at /history/<note-uuid>/<version-uuid>. Browser back works.
- Layout: the history takes the board's place. The side list (Notes, Reminders, Labels, Archive, Trash) stays exactly as on the board; its links go back to the board views.
- The current note's title sits in the exact spot of the "Take a note" bar. If the title is empty, use the same fallback the board cards use.
- Controls: a sort with "Newest first" (default) and "Oldest first", plus the same grid/list toggle as the board. History opens in the board's current layout.
- Versions: list every previous version as a note card, using the same card component and styles as the board (title, preview, color). The small history entries (§9) stay in time order between the cards, shown compactly.
- Cards behave like board cards: tap or click a card to open it. Remove the "Open" button. Keep the select checkbox and the Compare button (green and red, as in task 10).
- An opened version: remove the "Read-only" label. Show the version's title and body in the same positions the editor uses, as plain text that can't be edited.
- Color changes still never appear. Keep the "Back to note" action.
Keep the change scoped to history and routing. Reuse Board pieces; don't duplicate them.
Always write tests for the feature you're building, before or alongside the code. Then run ./tests/run-all.sh; every test must pass. Report.
```

**Done when:**
- Unit tests: both sort orders of versions and entries; the default is newest first.
- Component tests: the side list renders on history; the title sits in the "Take a note" spot; version cards use the board card; there's no "Open" button and no "Read-only" label; an opened version can't be edited.
- A Playwright test (`web/e2e/history.spec.ts`): edit a note twice, open /history/<id> directly, toggle grid and list, switch the sort, click a card to open it, press back, compare two.
- `./tests/run-all.sh` exits 0.
