# 17.11 · Reuse shared code in the web app

**Goal:** Pull the repeated web code into shared modules and use them everywhere it repeats. Nothing a user sees or does changes.

**Spec:** Flow §17 (file structure: shared UI in `ui/`, rules in `domain/`, database code only in `data/`). The owner approved this after checkpoint 1. Schema: none.

**Model:** Claude Opus 5.5.

**Prompt:**

```text
Read AGENTS.md, brief.md, and section 17 of docs/Tracepad-Full-Flow.md. Then read web/src/features/editor/NotesHome.tsx and Editor.tsx, web/src/features/board/Board.tsx, web/src/features/history/History.tsx, web/src/features/labels/NoteMeta.tsx, web/src/features/reminders/ReminderControl.tsx, web/src/data/notes.ts and reminders.ts, and every .css file under web/src.
Do task 17.11. This is a refactor. Behavior, text, the DOM, styles, and stored data stay the same. The owner approved this.
There is no new common/ folder. Shared code goes where section 17 puts it: shared React pieces and CSS in web/src/ui/, pure rules and formatting in web/src/domain/, database helpers in web/src/data/.
These are the known repeats. Fix them first, then look for others of the same kind:
1. Popovers: ReminderControl, NoteMeta, and Editor each add their own pointerdown, mousedown, click, and Escape listeners to close a panel. Make one hook in ui/ (for example useDismiss) and use it in all three.
2. Note actions: NotesHome has a modal version and a card version of each action: changePin and pinCard, changeArchive and archiveCard, changeColor and colorCard, toggleLabel and toggleCardLabel, addLabelByName and addCardLabel. Keep one version of each that takes a noteId. The open modal passes its own note's id.
3. Data writes: notes.ts and reminders.ts each define historyEvent, and several writers build the same outbox row. Make one helper in data/ for the history entry and one for the outbox row, and use them in every writer.
4. Small formatters: the card heading and label, the days-left text, the reminder title, and date padding move to domain/ next to editedDate if more than one file needs them.
5. CSS: the button reset (no border, transparent background, inherited font, pointer cursor) is repeated across feature files. Put one base class or rule in ui/ and use it. Feature files keep only their own differences.
Don't rename the public behavior, change the IndexedDB schema, or touch the tests' expectations. Tests may need new imports only.
Always write tests for the feature you're building, before or alongside the code. Write unit tests for each new shared helper and hook. Then run ./tests/run-all.sh; every test must pass. Report each repeat you removed, with before and after file names, and each one you chose to leave, with the reason.
```

**Done when:**

- Each of the five repeats above has one shared version, used by every place that had a copy.
- The new hook and helpers have their own unit tests.
- No user-facing text, DOM, or stored rows changed. The existing tests pass with only import changes.
- `./tests/run-all.sh` exits 0.
