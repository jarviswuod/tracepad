# 14.3 · Search each page on its own, and mark archived notes

**Goal:** Changing page clears the search and runs it on that page's notes. An archived note brought in by search gets a blue bar across its top, on the card and in the open modal.

**Spec:** Flow §12 (search). The owner approved two changes after task 14.2. On the Trash page, search covers trashed notes. Everywhere else they stay out. Schema: none.

**Model:** Claude Sonnet 5.5.

**Prompt:**

```text
Read AGENTS.md, brief.md and section 12 of docs/Tracepad-Full-Flow.md. Then read web/src/features/board/Board.tsx (openPath copies location.search), web/src/features/search/SearchControls.tsx and searchUrl.ts, web/src/features/editor/NotesHome.tsx, web/src/domain/search.ts, web/src/features/board/board.css and web/src/ui/note-modal.css.
Do task 14.3. The owner approved both of these:
1. Search follows the page. The side list currently carries ?text= and archived=1 onto the next page, so the box and the results look the same on Home, Archive, Trash and a label.
   - Opening another page drops both params and clears the box. Each page starts with no search.
   - A search then runs on that page's own notes. Home stays as it is now: not archived, not trashed, and archived notes only when the switch is on. Archive searches archived notes only. Trash searches trashed notes only. A label searches that label only, and the switch still decides whether its archived notes count. Reminders searches whatever that view lists.
   - Keep the matching rules: case doesn't matter, current title, body and checklist items only, never old versions. Typing still updates the current page's URL, and a refresh still keeps those words.
2. When an archived note is shown because the switch is on, mark it. Add a solid blue (#1a73e8) bar, 3px, across the very top of the card, exactly as wide as the card, in both grid and list. Opening that note puts the same bar across the top of the modal, exactly as wide as the modal. Keep the "Archived" word. Notes that aren't archived get no bar. The Archive page itself is unchanged, since every card there is archived.
Don't change anything else about search or the board.
Always write tests for the feature you're building, before or alongside the code. Then run ./tests/run-all.sh; every test must pass. Report.
```

**Done when:**
- A test: going from `/home?text=apple&archived=1` to Archive, Trash, a label or Reminders lands with an empty box and no search params.
- Domain tests: the same word finds only that page's notes (home, archive, trash, one label). A trashed note never matches on Home.
- A component test: an archived result has the blue top bar in grid and in list; a normal card doesn't. The open modal of that archived note has the bar, and it is as wide as the modal.
- A Playwright test: search on Home, open Archive, and the box is empty. Search there and only archived notes show. Turn the switch on at Home and the archived card's blue bar runs the full width of the card. Open it and the modal has the same bar.
- `./tests/run-all.sh` exits 0.
